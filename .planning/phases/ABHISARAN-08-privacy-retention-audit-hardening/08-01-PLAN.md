# Plan 08-01: Privacy Incident Finite State Machine & 2-Hour Notification Clock (SEC-01)

## Overview
Implement the 5-state Privacy Incident finite state machine (`DETECTED` -> `CONTAINED` -> `NODAL_NOTIFIED` -> `DISTRICT_DIRECTED` -> `CLOSED`) with an automated 2-hour statutory notification clock, overdue escalation flagging, and strict Zero-PII non-identifying description validation.

## Requirements
- **SEC-01**: Automated privacy incident creation upon suspected PII with 2-hour notification clock.

## Proposed Changes

### 1. Backend Domain & Logic
- Update `PrivacyIncident.java` (or extend with status enum: `DETECTED`, `CONTAINED`, `NODAL_NOTIFIED`, `DISTRICT_DIRECTED`, `CLOSED`).
- Create `PrivacyIncidentRepository.java`.
- Create `PrivacyIncidentService.java`:
  - Enforces the 5-state progression.
  - Computes remaining minutes on the 2-hour notification countdown from `detectedAt`.
  - Computes `isOverdue` if `nodalNotifiedAt == null` and elapsed time exceeds 120 minutes.
  - Ensures incident description never contains PII regex patterns.
- Create `PrivacyIncidentController.java` exposing:
  - `GET /api/v1/privacy/incidents`
  - `POST /api/v1/privacy/incidents`
  - `PATCH /api/v1/privacy/incidents/{id}/contain`
  - `PATCH /api/v1/privacy/incidents/{id}/notify-nodal`
  - `PATCH /api/v1/privacy/incidents/{id}/district-direction`
  - `PATCH /api/v1/privacy/incidents/{id}/close`

### 2. Verification
- Create unit test suite `PrivacyIncidentTests.java` testing state transitions, 2-hour clock calculation, overdue detection, and Zero-PII sanitization.
