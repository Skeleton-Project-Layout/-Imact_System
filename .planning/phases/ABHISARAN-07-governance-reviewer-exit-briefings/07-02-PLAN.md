# Plan 07-02: Factual Corrections, Independent Reviewer Pack & Admin Governance UI (GOVN-02, GOVN-03)

## Overview
Implement the immutable factual correction workflow retaining original values, the Independent Reviewer declaration pack with mandatory COI checks and methodology limitation notes, and integrate governance views into Front B (`/admin/*`).

## Requirements
- **GOVN-02**: Immutable, audited correction workflow retaining original values and verifier justification.
- **GOVN-03**: Independent reviewer declaration, conflict-of-interest check, and methodology limitation notes.

## Proposed Changes

### 1. Backend Domain & Logic
- Create `FactualCorrection.java` entity in `org.aeht.abhisaran.model`:
  - Fields: `id`, `deliveryPointCode`, `evidenceId`, `metricTarget`, `originalValue` (immutable), `correctedValue`, `justification`, `status` (`SUBMITTED`, `VALIDATED`, `REJECTED`), `submittedBy`, `submittedAt`, `validatedBy`, `validatedAt`, `decisionNotes`.
- Create `ReviewerDeclaration.java` entity in `org.aeht.abhisaran.model`:
  - Fields: `id`, `reviewerName`, `designation`, `organization`, `areaOfExpertise`, COI booleans (`noReportingLineToFieldTeam`, `notAehtEmployeeOrBoard3Years`, `confidentialityAgreed`), `districtApprovalStatus` (`PENDING`, `ACCEPTED`, `ALTERNATIVE_PROPOSED`, `VETOED`), `districtDecisionBy`, `methodologyLimitationNotes` (mandatory), `disagreementsLogged`, `recommendations`, `endorsementStatus`.
- Create `FactualCorrectionRepository.java` and `ReviewerDeclarationRepository.java`.
- Create `FactualCorrectionService.java` with logic:
  - Preserves `originalValue` immutably.
  - Role-gated validation (`DISTRICT_NODAL_OFFICER` per RBAC §11).
  - Updates linked evidence verification status to `CORRECTED` on validation.
- Create `ReviewerService.java` with logic:
  - Strictly enforces COI requirements (rejects if any COI boolean is false).
  - Strictly enforces non-empty `methodologyLimitationNotes` (must record limitations, not just blanket endorsement).
  - Gated District approval/veto actions.
- Create `GovernanceController.java` with endpoints:
  - `GET /api/v1/governance/corrections`
  - `POST /api/v1/governance/corrections`
  - `PATCH /api/v1/governance/corrections/{id}/validate`
  - `GET /api/v1/governance/reviewer-pack`
  - `POST /api/v1/governance/reviewer-pack/declaration`
  - `PATCH /api/v1/governance/reviewer-pack/district-decision`

### 2. Frontend Governance Views
- Create `frontend/src/admin/ExitBriefingsView.jsx`:
  - Lists exit briefings for pilot delivery points with status badges (`Factual Observations Shared`, `Shared but not signed (Non-adverse)`).
  - Displays non-adverse reassurance note and correction window timer.
- Create `frontend/src/admin/FactualCorrectionsView.jsx`:
  - Displays audit trail of corrections showing original vs. corrected values, justifications, and validation status.
- Create `frontend/src/admin/ReviewerPackView.jsx`:
  - Displays Independent Reviewer profile, verified COI checks, methodology limitation notes, and District endorsement status.
- Integrate tabs into `frontend/src/admin/AdminShell.jsx`:
  - Navigation links for "Exit Briefings", "Corrections", and "Reviewer Pack".

### 3. Verification
- Create unit tests `FactualCorrectionTests.java` and `ReviewerDeclarationTests.java`.
- Run frontend build (`npm run build`) to ensure zero errors.
