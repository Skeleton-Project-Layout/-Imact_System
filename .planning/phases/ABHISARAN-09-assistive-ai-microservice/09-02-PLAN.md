# Plan 09-02: Strict Write-Path Isolation & Security Test Suite (AIMS-02)

## Overview
Implement the backend Spring Boot assistive AI integration boundary and comprehensive negative security tests proving that the AI service has strictly zero write access to scores, flags, priorities, or verification states.

## Requirements
- **AIMS-02**: Complete write-path isolation ensuring AI cannot write to scores, flags, priorities, or verification states.

## Proposed Changes

### 1. Backend Integration & Boundary
- Create `backend/src/main/java/org/aeht/abhisaran/ai/AiAssistiveClient.java`:
  - Enforces read-only consumer pattern: sends verified evidence IDs and text; consumes only `DRAFT` response objects.
  - Rejects any output attempting to dictate official scores or verification statuses.
- Create `backend/src/main/java/org/aeht/abhisaran/ai/AiAssistiveController.java`:
  - Exposes assistive drafting endpoint to authorized administrative users (`/api/v1/ai/draft-action-brief`).
  - Flags every response with `humanReviewRequired = true` and `status = "DRAFT"`.

### 2. Security & Isolation Tests
- Create `backend/src/test/java/org/aeht/abhisaran/ai/AiIsolationSecurityTests.java`:
  - Introspects AI response DTOs and API boundary to prove:
    1. Zero write paths to `ACSResult`, `ScoringComponent`, `FlagEvaluation`, `PriorityActionItem`, or `EvidenceVerificationHistory`.
    2. AI client cannot mutate evidence verification status.
    3. AI client cannot overwrite priority scores or feasibility flags.
    4. AI responses strictly carry `status == 'DRAFT'` and `humanReviewRequired == true`.

### 3. Verification
- Verify tests pass with mock/unit assertions.
